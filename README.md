# Roast Point — Next.js frontend

Next.js 16 (App Router), React 19, TypeScript, обычный CSS, иконки Lucide.
Интерфейс по приложенным макетам: светлые панели, коричневая навигация,
фотографии товаров, мобильное меню и корзина.

## Локальный запуск

Нужен Node.js 22 или 24. Из папки «Программная инженерия»:

```powershell
cd frontend
npm install
npm run dev
```

Откройте http://localhost:3000. Для воспроизводимой установки можно использовать
pnpm 11.25.0: `pnpm install --frozen-lockfile`, затем `pnpm dev`.
В репозитории есть pnpm-lock.yaml с зафиксированными версиями.

Проверка и production:

```powershell
npm run typecheck
npm run build
npm start
```

## Подключение к backend

Запустите обновлённый Spring Boot backend из соседней папки backend. По умолчанию Next.js
обращается к http://localhost:8080. Чтобы изменить адрес, скопируйте
`.env.example` в `.env.local`, измените BACKEND_URL и перезапустите Next.js.
BACKEND_URL — адрес только для серверной части, браузер его не использует.

Браузер обращается к /api на том же адресе Next.js. Route Handler передаёт
запрос в Spring Boot, cookie JSESSIONID и CSRF-токен. Cookie устанавливается
на адрес фронтенда; отдельная настройка CORS не нужна. При входе и выходе
CSRF-токен сбрасывается, при следующем изменении запрашивается заново.
Токены и пароли не сохраняются в localStorage.

Тестовые пользователи backend: cashier1, barista1, admin1. Их начальный пароль
задаётся DEMO_PASSWORD до первого запуска backend, см. корневой README.md.
Если /api/auth/me возвращает 404, остановите старый экземпляр Spring Boot
и запустите актуальную версию из этого репозитория.

## Экраны

- Вход и выход из сессии, восстановление действующей сессии после обновления.
- Меню: поиск, категории, карточка товара, корзина, количество, оформление заказа.
- История: пагинация по 50 записей, просмотр состава каждого заказа.
- Очередь: все активные заказы, обновление каждые 10 секунд. Бариста начинает
  приготовление и отмечает готовность; кассир выдаёт готовый заказ.
- Состав заказа: сумма, этапы приготовления, печатная версия.
- Отчёт администратора: период, сумма выданных заказов, количество, средний заказ,
  диаграмма и таблица по дням. Данные приходят из /api/reports/sales.
- Администратор создаёт и изменяет позиции меню, меняет доступность и добавляет
  категории через настройки. Цены в новых заказах определяет backend.

Кнопка «Посмотреть демо» открывает самостоятельный деморежим без backend.
Он явно обозначен; роль переключается в верхней полосе. Заказы, корзина,
статусы и редактирование меню работают в памяти страницы. После обновления
все демонстрационные изменения сбрасываются. Отчёт в деморежиме использует
образец данных, а не реальные продажи.

Оплата, скидки, размеры и добавки не отправляются: текущий API их не поддерживает.
Вместо кнопки «К оплате» из макета используется «Оформить заказ».
Документ для печати явно обозначен как информационный, без выдуманных
платёжных реквизитов, QR оплаты и признаков фискального чека.
Фотографии иллюстративные; точные параметры товара уточняются в кофейне.

## Docker

Из соседней папки backend: `docker compose up --build -d`. Фронтенд доступен на
http://localhost:3000, backend внутри сети Compose — http://app:8080.
Порт фронтенда можно изменить переменной FRONTEND_PORT.
